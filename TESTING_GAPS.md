# Testing Gaps: Spring Boot 3.2.5 Upgrade

## Verified in This Environment

- All 68 unit tests pass (JUnit 5)
- Application context loads successfully (Spring Boot 3.2.5 + DGS 8.7.1)
- Compilation: zero errors across 120 Java source files
- Spotless formatting: all files pass Google Java Format
- JaCoCo report generation succeeds
- JWT token generation and parsing works with jjwt 0.12.5

## Cannot Verify in This Environment

### Integration Tests
- **REST API endpoint testing**: No integration test suite runs the full HTTP stack; the `@WebMvcTest` slices mock the service layer. Full end-to-end REST testing (POST/PUT/DELETE with real database) is not covered.
- **GraphQL query/mutation testing**: No integration tests execute real GraphQL queries against the DGS 8.x / Spring for GraphQL stack. The schema inspection was disabled (`spring.graphql.schema.inspection.enabled=false`) and should be validated with real queries.
- **Database migration testing**: Flyway migrations run during context load tests with SQLite, but production database compatibility (if non-SQLite) is untested.

### E2E / Selenium Tests
- **Selenium E2E suite**: The `seleniumTest` Gradle task (TestNG-based) is excluded from the standard `test` task. These tests require a running application server and browser, which are not available in this build environment.
- **Frontend integration**: The Next.js frontend (`frontend/`) is not built or tested as part of this migration.

### Performance Tests
- **No performance regression testing**: No load tests, benchmarks, or startup-time comparisons between Spring Boot 2.6.3 and 3.2.5.
- **Memory/GC profiling**: No comparison of heap usage or GC behavior between Java 11 and Java 17.

### Security Scans
- **Dependency vulnerability scan**: No OWASP Dependency-Check or Snyk scan was run against the updated dependencies.
- **Spring Security configuration audit**: The migration from `WebSecurityConfigurerAdapter` to `SecurityFilterChain` was a structural change; authorization rules should be manually verified to ensure no security regression.
- **CORS configuration**: While preserved verbatim, the wildcard `*` origin policy should be reviewed for production deployment.

### Compatibility Tests
- **Downstream service compatibility**: If this service is consumed by other services, API contract compatibility (REST and GraphQL schemas) should be verified.
- **JWT token backward compatibility**: The migration from jjwt 0.11.x to 0.12.x changed the signing algorithm selection (from explicit HS512 to auto-detection via `Keys.hmacShaKeyFor()`). Tokens generated by the old version may use a different algorithm than tokens generated by the new version. Existing tokens in flight during deployment will still parse correctly (the parser auto-detects), but this should be validated in a staging environment.
- **MyBatis 3.0.x compatibility**: MyBatis Spring Boot Starter 3.0.x may have behavioral differences from 2.2.x; complex mapper queries should be regression-tested.

### Build/Deploy
- **CI/CD pipeline**: The GitHub Actions workflows were previously removed from this repo. CI behavior with the new Gradle 8.7 wrapper and Java 17 should be validated.
- **Docker image build**: If containerized, the base image must be updated from Java 11 to Java 17.
- **Production startup**: `bootRun` was not executed in this environment; the application should be started and smoke-tested in a staging environment.
